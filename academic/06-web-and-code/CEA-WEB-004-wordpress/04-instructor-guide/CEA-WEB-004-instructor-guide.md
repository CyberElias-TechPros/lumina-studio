**Do not distribute.** Keys in Section 7.

## 1. What this course is

The client-work engine: install → theme → content → business features → handover. Every session produces a live artefact; S6 demands a verified backup as the price of certificates.

## 2. Preparation

Two practice environments per student (shared class install + sandbox/LocalWP) · pre-broken sandbox for the S4 autopsy ·
backup plugin pre-installed · Paystack TEST keys (sandbox) · printed handover-sheet cards ·
loaner phones for final; SMTP sandbox credentials if using email forms.

## 3. Delivery model

105 min: 0–10 demo from last session · 10–25 whiteboard teach · 25–45 live build · 45–70 pair work · 70–95 solo · 95–110 KC · 110–120 handover-minute close.

## 4. Failure points

- S1: default "admin" username slips in — enforce new-owner admin creation.
- S2: nulled theme temptation — ZERO tolerance; show a phone-home screenshot from a real malware incident.
- S3: page builder sprawl — keep the class on core blocks this term; builders are a deliberate later choice.
- S4: five-question test gets ritualised — make every team SAY all five aloud.
- S5: SMTP skipped → leads silently vanish → angry client → reputation loss. Non-negotiable in-class.
- S6 gate: backup file on demand; live URL; handover role-play. "I'll do it at home" = reassess.

## 5. Assessment guidance

A1 (S3 submit): sandbox walk-through + backup file check. Final: live multi-page site, form round-trip, 2FA admin, backup on demand, handover role-play (2 min). Show-and-tell: the handover conversation is the job.

## 6. Equity & access

Shared sandboxes; loaner phones; offline notes; home internet not required (installs in-class); printed cards for the handover script.

## 7. Knowledge-check keys

KC1: 1) theme=look · plugin=features. 2) Readable keyword-friendly URLs. 3) Brute-force guess #1. 4) True timestamps & scheduling. 5) Offline practice sandbox.
KC2: 1) Update-survival. 2) Popularity/recency/ratings (+speed). 3) Identity/colours/menus classic. 4) Malware/phone-home. 5) Child theme or Customizer only.
KC3: 1) Evergreen vs dated. 2) One edit everywhere. 3) Settings→Reading→static page. 4) Theme decides menu location. 5) A11y + SEO + resilience.
KC4: 1) Structure vs keywords. 2) Trusted code sprawl kills sites. 3) Recency/installs/reviews/support/data. 4) Deactivate-all → one-by-one → last-in suspect. 5) Settings→Discussion → hold.
KC5: 1) Host mail = spam; SMTP = delivery. 2) Silent human-friendly bot filter. 3) wa.me/234…?text= 4) Woo catalog + Paystack ₦. 5) Test mode until a round-trip order.
KC6: 1) Files + DB. 2) Quarterly/any risky change. 3) Stolen passwords insufficient. 4) Disables dashboard code editor. 5) URLs/creds/backups/retainer.

## 8. Expected outputs & calibration

S1: Lagos timezone set room-wide by minute 30. S3: static homepage + menu live everywhere. S5: at least one test purchase cleared in-class. S6: every student produces two archives (files+DB) without help.

## 9. Rubric (0–4)

0 default-admin, no backup · 1 local-only · 2 live with form but no 2FA/backup · 3 live + hardened + backed-up + handover done · 4 3 + client-retainer pitch that lands. Gate: live URL + backup on demand.
