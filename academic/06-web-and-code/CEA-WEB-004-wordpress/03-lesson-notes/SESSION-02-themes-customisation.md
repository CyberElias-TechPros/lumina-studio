## 0–10 · Review & warm-up

Theme candidates named — favourites usually chosen by screenshot, not by support quality; today we choose like adults.

## 10–25 · Teaching block

**Choosing like a professional.** Active installs >100k · recently updated · rated ≥4.5 · support forum alive · LIGHTWEIGHT (speed scores!) · block-theme vs classic · avoid themeforest-Nulled forever.
**Customizer vs Site Editor.** Classic → Appearance → Customize (identity, colors, menus, widgets, homepage) · block themes → Appearance → Editor (templates, patterns).
**Child themes — the law.** Never edit parent theme files; updates erase you. Child theme = `style.css` with headers + `functions.php` stub; your tweaks live there; parent updates safely.
**What breaks themes.** PHP version bumps · page-builder sprawl · jQuery fights between theme+plugin · nulled themes with phone-home malware — "free" is the most expensive word in web work.

## 25–45 · Guided demonstration

Live: activate Astra-class free theme on sandbox; child theme created via plugin OR minimal files; change ONLY brand colour, font, hero text in Customize; break-and-restore via parent reset; room votes on Lighthouse-visible bloat (no slider plugin!).

## 45–70 · Guided practice

Pairs: switch their sandboxes to the chosen theme; set logo/colours/menu location; create child theme with one CSS tweak (brand button); partner verifies parent files untouched.

## 70–95 · Independent practice

Solo: **themed identity** — your sandbox wearing its brand: logo (or wordmark), brand colour, nav menu, hero text, child-theme proof. Screenshots to workbook.

## 95–110 · Correction & check

KC2: (1) Child theme solves. (2) Theme selection trio. (3) Customizer for what. (4) Nulled themes danger. (5) Update-safe customisation rule.

## 110–120 · Summary & next session

Dressed and stable. S3: fill it — pages, blocks, menus.
