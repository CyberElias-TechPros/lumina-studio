## 1. Identity

- **Title:** Mobile App Development · **Department:** Web & Code · **Level:** Intermediate
- **Duration:** 4 weeks · 8 sessions · 2/week · 105 min · **840 guided minutes**
- **Fee:** ₦60,000 · **Cohort:** max 12
- **Delivery:** On-site lab; Android Studio or Expo Go route; at least one testing phone per 2 students

## 2. Description

Scope a first version honestly, design mobile screens that respect platform conventions, build screens +
navigation + state in a modern framework (React Native/Expo route), handle lists, storage and one API,
and walk everything on a real device or emulator — documented like a professional prototype.

## 3. Purpose

Every SME wants "an app". Most need a disciplined first version, not a fantasy. This course builds the thinking and the build.

## 4. Audience

Intermediate students with prior framework exposure (web-development completion recommended but not mandatory) · technical founders validating an app idea · developers adding mobile.

## 5. Entry requirements

Basic programming literacy (variables, functions, events — e.g. CEA-WEB-003 weeks 1–8 or equivalent) · laptop; phone optional with Expo Go.

## 6. Learning outcomes

1. Scope an idea into a v1: one user, one job, three screens from first sketch to shipped prototype.
2. Design to platform conventions: touch targets, navigation patterns, typography, safe areas.
3. Build screens, navigation, lists, forms and local storage; fetch one API with loading/error/empty states.
4. Test on device/emulator; debug common mobile bugs; prepare for store submission requirements.

## 9. Practical exercises

V1-scope whiteboard (S1) · screen flow paper prototype (S2) · first build (S3) · nav wiring (S4) · storage drill (S5) · API with failure states (S6) · device test day (S7) · final (S8).

## 10. Assessment

| Component                                                                            | Weight |
| ------------------------------------------------------------------------------------ | ------ |
| Knowledge checks (8 × 5)                                                             | 10%    |
| Workbook practicals                                                                  | 25%    |
| Assignment A1 — v1 scope pack: one-user story, 3-screen flow, wireframes, build plan | 15%    |
| Final project — working multi-screen prototype on device/emulator                    | 40%    |
| Show-and-tell — walk your app, own your cut list                                     | 10%    |

**Critical gate:** the prototype must run the core user loop unassisted (launch → do the job → see the result) on a device or emulator in front of the assessor; a slide deck is not an app; failure = reassess once.

## 11. Critical behaviors

Cut scope before adding features · test on a real battery-hot phone · empty states everywhere · ship the skeleton before the skin · charge for v2 after v1 proves out.

## 12. Learning barriers

Feature-creep fatalism; xcode/android-studio config hell — Expo-route to the rescue; "one more screen" syndrome.

## 13–16. Delivery · QA · Resources · Completion

Loaner Android phones; Expo accounts sandboxed; personal laptops recommended; classroom Wi-Fi. Attendance ≥ 6/8; gate passed; prototype APK/Expo link filed; feedback form before certificate.
