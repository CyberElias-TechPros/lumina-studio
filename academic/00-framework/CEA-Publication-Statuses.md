## Publication statuses

| Status                      | Meaning                                      | What the student receives   |
| --------------------------- | -------------------------------------------- | --------------------------- |
| **Outline**                 | Topics, objectives, timing only              | A topic list. Not a lesson. |
| **Lesson note**             | Full 14-part lesson-note structure           | A document that teaches.    |
| **Complete lesson package** | Lesson note + practice activity + assessment | The full experience.        |

Rule: a lesson must never be marketed or presented as a "lecture" / "complete note" while it is in
Outline or note-only state. LMS labels and the course manual status tables must match reality.

## Pre-publication checklist (per document)

- [ ] Accuracy: every technical instruction tested on the machines students will use
- [ ] Alignment: teaches what the outcome states; assessed on what is taught
- [ ] Readability: a beginner can follow without an instructor present
- [ ] Practical activity present in every module
- [ ] Time-fit: deliverable in the allocated minutes (105 for core sessions)
- [ ] Assets legal: images, datasets, templates owned or licence-cleared
- [ ] Accessibility: readable text, adequate contrast, no meaning by colour alone, prints B/W
- [ ] Document control footer present; version and status correct
- [ ] Instructor guide matches the note (same steps, same files)
- [ ] Change history updated

## QA questions for a whole course

- Is the course honest about outcomes (introductory competence, not mastery)?
- Is the duration coherent with the session count (2 weeks ≈ 4 sessions ≈ 6–8 contact hours)?
- Are prerequisites consistent with the on-ramp positioning?
- Is the final project artefact demonstrable in a 15-minute observation?
- Does the assessment plan total 100% and include the mandatory practical gate?
