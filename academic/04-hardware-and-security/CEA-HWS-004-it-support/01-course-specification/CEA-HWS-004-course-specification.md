## 1. Identity

- **Title:** IT Support · **Department:** Hardware & Security · **Level:** Beginner
- **Duration:** 3 weeks · 6 sessions · 2/week · 105 min · **630 guided minutes**
- **Fee:** ₦40,000 · **Cohort:** max 15
- **Delivery:** On-site classroom + phone-support simulation room; machines with browsers

## 2. Description

The people-first side of IT: helpdesk triage, priority/SLA thinking, structured troubleshooting (reproduce,
isolate, fix, confirm), supporting nervous non-technical users with dignity, password/account resets, printers,
software installs, updates, ticket notes and a ten-fault playbook you'll actually run on the job.

## 3. Purpose

Most IT failures are human interfaces, not machines. This course produces the support tech who makes the
CFO feel safe and the intern feel seen, every ticket.

## 4. Audience

NYSC members in IT units · office admins doubling as tech · graduates targeting helpdesk roles · junior sysadmins.

## 5. Entry requirements

Basic computer use and calm temperament; prior CEA-OFF-001 useful, not required.

## 6. Learning outcomes

1. Triage any fault report by priority, impact and SLA; run structured troubleshooting without guessing.
2. Communicate with non-technical users: patience, plain words, empathy, escalation judgment.
3. Resolve account/permission/printer/software faults; handle updates and patches sanely.
4. Log tickets, write knowledge-base notes the next tech can use, keep asset records.
5. Escalate correctly — know what you don't know, and say so with a handoff.

## 10. Assessment

| Component                                                                | Weight |
| ------------------------------------------------------------------------ | ------ |
| Knowledge checks (6 × 5)                                                 | 10%    |
| Workbook practicals                                                      | 25%    |
| Assignment A1 — five knowledge-base articles                             | 15%    |
| Final project — support simulation (observed calls) + ten-fault playbook | 40%    |
| Show-and-tell — the ticket that taught you most                          | 10%    |

**Critical gate:** simulation — at least two faults diagnosed with correct escalation judgment (including one "this is out of my depth — escalating to L2 with notes"); failure = reassess once.

## 11. Critical behaviors

Confirm the fix with the USER before closing · never remote-takeover without stated consent · notes before you forget · say "I don't know yet" without shame.

## 12. Learning barriers

Tech-ego ("we'll show that user"); silence ("still broken" reported as nothing); documentation debt.

## 13–16. Delivery · QA · Resources · Completion

Seeded fault lab; phone-sim headsets; ticket templates; printed escalation matrix. Attendance ≥ 4/6; gate passed; playbook filed; feedback form before certificate.
