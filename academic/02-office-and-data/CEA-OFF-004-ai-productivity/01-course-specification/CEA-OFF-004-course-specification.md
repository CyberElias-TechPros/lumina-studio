  approved AI tools (free tiers) or downloaded models

## 2. Description

Students leave with one living, documented AI workflow for a real recurring task of theirs — the
prompts, the verification steps, and the parts they keep human. The course teaches what language
models actually are (and are not), how to prompt with context, constraints and examples, how to
verify generated claims, and how to write a personal policy on data they will never share with AI.

## 3. Purpose

AI tools are now in every office. Undisciplined use creates confident errors, privacy leaks and
fabricated citations. This course produces a critical, capable user — not an evangelist, not a
scoffer — who can delegate a first draft and still own the final truth.

## 4. Audience

- Working adults, job-seekers, students and business owners using ChatGPT/Copilot-class tools
- Anyone who has mixed feelings about AI and wants a disciplined way to use it

## 5. Entry requirements

- Basic computer confidence (CEA-OFF-001 or equivalent) · browser literacy
- A smartphone or laptop from home helps for the between-session workflow audit (optional)

## 6. Learning outcomes

1. Explain what LLMs are good at, where they fail (hallucination, staleness, bias) and choose a suitable tool.
2. Write prompts with role, context, constraints, examples and output format; iterate without starting over.
3. Use AI for research and drafting while verifying every factual claim independently.
4. Detect hallucinations and bias in generated output and document verification.
5. Apply a written personal AI policy covering private data, workplace and academic honesty.

## 9. Practical exercises

- Failure-mode gallery (guided): five real hallucination examples to spot.
- Prompt iteration lab (guided): same task, bad prompt → context prompt → few-shot prompt; compare.
- Verified summary drill (guided): AI summary of a real article; student annotates checked vs unchecked claims.
- Reusable prompt library (independent): five tested prompts for recurring tasks.
- Personal AI policy (independent): one page, signed.

## 10. Assessment

| Component                                                           | Weight |
| ------------------------------------------------------------------- | ------ |
| Knowledge checks (4 × 5)                                            | 10%    |
| Workbook practicals                                                 | 25%    |
| Assignment A1 — verified AI-assisted deliverable                    | 15%    |
| Final project — documented personal AI workflow + policy (observed) | 40%    |
| Show-and-tell — walk your workflow, show the verification loop      | 10%    |

**Critical gate:** final deliverable verification log — every factual claim checked, sources named;
gate failure = reassess once.

## 11. Critical behaviors

- Verifies before trusting; cites sources for any claim leaving the building.
- Writes the "why" beside each prompt so the workflow survives a colleague's hand.
- Never pastes private/client data into a tool; says "no" to a tool that asks for it.

## 12. Learning barriers

- **Automation bias** (trusting fluent text): countered by mandatory claim-checking drills and the
  "trusted but verified" stamp on every printed artefact.
- **Prompt magic mindset** (one perfect prompt exists): teach iteration as the normal path.

## 13. Delivery

Live tools projected; every student drives a machine. Printed model-cards (capabilities/failure
modes). Honest benchmarking — no vendor demos designed to impress.

## 14. Quality assurance · 15. Resources · 16. Completion

Pilot reviewed against spec; tools list kept current each term. Resources: browser machines,
approved tool accounts, printed verification sheets, sample hallucination corpus. Completion:
attendance ≥ 3/4, gate passed, workflow + policy filed to portfolio, feedback form before certificate.
